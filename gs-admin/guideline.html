Guideline: Blogs Feature Backend

  1. Dashboard
  2. Blogs Backend Guideline
v1.0

1) Overview

This document describes a pragmatic backend design for a Blogs feature powering GS Admin. It covers user authentication, creating/updating/deleting posts, organizing content with categories and tags, and integrating the API with existing admin pages (new-blog.html and all-post.html). You can implement it in any web backend stack (Node/Express, Laravel, Django, Rails, etc.). Examples below use JSON over HTTP with JWT-based authentication.

Minimal viable scope: secure login, CRUD for posts, publish/draft state, slugs, pagination, and basic organization (categories/tags).

2) Authentication & Authorization

  • Use email/password login returning a short-lived access_token (JWT) and long-lived refresh_token.
  • Protect all content endpoints with Bearer access tokens.
  • Roles: admin, editor, author (author can manage own posts; editor/admin can manage all).
  • Password hashing with bcrypt/Argon2. Enforce strong passwords and rate limit login attempts.
{
  "POST /api/auth/login": {
    "body": {"email": "user@example.com", "password": "string"},
    "200": {"access_token": "jwt", "refresh_token": "jwt", "user": {"id": 1, "name": "...", "role": "editor"}},
    "401": {"error": {"code": "INVALID_CREDENTIALS", "message": "..."}}
  },
  "POST /api/auth/refresh": {
    "body": {"refresh_token": "jwt"},
    "200": {"access_token": "jwt"},
    "401": {"error": {"code": "TOKEN_INVALID", "message": "..."}}
  },
  "POST /api/auth/logout": {
    "auth": "Bearer access",
    "body": {"refresh_token": "jwt"},
    "204": {}
  }
}

3) Data Models

Relational (SQL) suggestion
users(id PK, name, email UNIQUE, password_hash, role ENUM('admin','editor','author'), created_at, updated_at)
posts(id PK, author_id FK users.id, title, slug UNIQUE, excerpt, content_html, content_text, cover_url, status ENUM('draft','published'),
      published_at NULLABLE, meta_title, meta_description, created_at, updated_at)
categories(id PK, name UNIQUE, slug UNIQUE, created_at, updated_at)
tags(id PK, name UNIQUE, slug UNIQUE, created_at, updated_at)
post_categories(post_id FK posts.id, category_id FK categories.id, PRIMARY KEY(post_id, category_id))
post_tags(post_id FK posts.id, tag_id FK tags.id, PRIMARY KEY(post_id, tag_id))

Indexes: posts.slug, posts.status+published_at, posts.author_id, post_tags.tag_id, post_categories.category_id.

6) Integration with GS Admin UI

Connect the existing admin pages to the backend using fetch/XHR. Keep the load order: Bootstrap bundle → js/scripts.js. Example snippets:

new-blog.html (Publish, Save Draft)
<script>
async function api(path, opts={}) {
  const token = localStorage.getItem('access_token');
  const headers = Object.assign({ 'Content-Type': 'application/json' }, opts.headers||{});
  if (token) headers['Authorization'] = `Bearer ${token}`;
  const res = await fetch(`/api${path}`, Object.assign({}, opts, { headers }));
  if (!res.ok) throw await res.json();
  return res.status === 204 ? null : res.json();
}

async function saveDraft() {
  const title = document.getElementById('postTitle').value;
  const content = document.getElementById('postContent').value; // set by editor
  const body = { title, content_html: content, status: 'draft' };
  const created = await api('/posts', { method: 'POST', body: JSON.stringify(body) });
  // Handle success (toast, redirect)
}

async function publishPost(postId) {
  await api(`/posts/${postId}`, { method: 'PATCH', body: JSON.stringify({ status: 'published' }) });
}
</script>
all-post.html (List, Delete)
<script>
async function loadPosts(page=1) {
  const data = await api(`/posts?page=${page}&limit=20&sort=-created_at`);
  // Feed rows into Simple-DataTables
}
async function deletePost(id) {
  if (!confirm('Delete this post?')) return;
  await api(`/posts/${id}`, { method: 'DELETE' });
  await loadPosts();
}
</script>
For Quill/other rich text editors, store sanitized HTML on the server and also maintain a plain-text excerpt for previews (server can derive but allow override).

7) Validation & Error Format

// Error response format (suggested)
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "One or more fields are invalid",
    "details": [
      {"field": "title", "message": "Title is required"}
    ]
  }
}

// Common checks
- title: required, 1..200 chars
- content_html: required for publish
- status: draft|published
- categories,tags: existing slugs only; create-on-write optional (editor+)
- slug: auto-generate, unique, editable for admin/editor (validate)

8) Security

  • JWT with short expiration (e.g., 15m); refresh rotation with revocation list.
  • Role-based checks at route level; authors restricted to own posts.
  • Sanitize and validate HTML to prevent XSS; use an allowlist sanitizer server-side.
  • Rate limit login and write endpoints; enable CORS only for trusted origins.
  • Store media in object storage (S3/GCS) with signed uploads or via media endpoint.

9) Pagination, Sorting, Search

  • Use page and limit with bounds (1..100).
  • Sort syntax: prefix with - for descending. Allow fields: created_at, published_at, title.
  • Search across title, excerpt, content_text using full-text indexes when possible.

11) Testing

  -H "Content-Type: application/json" \
  -d '{"email":"editor@example.com","password":"secret"}'

# Create draft
curl -X POST https://api.example.com/api/posts \
  -H "Authorization: Bearer $ACCESS" -H "Content-Type: application/json" \
  -d '{"title":"Draft","content_html":"<p>Hi</p>","status":"draft"}'

# Publish
curl -X PATCH https://api.example.com/api/posts/123 \
  -H "Authorization: Bearer $ACCESS" -H "Content-Type: application/json" \
  -d '{"status":"published"}'

12) Future Enhancements

  • Revisions/history per post (audit log).
  • Scheduling posts with a background worker.
  • Content localization (i18n) with post_translations table.
  • Webhooks to rebuild static sites or invalidate CDN cache on publish.
  • Role customization and granular permissions.

Quick Tips
  • Keep API stateless; use JWT for auth.
  • Guard publish/update/delete with roles.
  • Normalize categories/tags; use slugs.
  • Return consistent error shapes.
  • Enable pagination on all list endpoints.
